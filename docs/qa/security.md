# Безопасность и устойчивость — проверка 30.10.2026

Сайт статический: нет сервера, аккаунтов и паролей, данные ученика (прогресс, настройки, группа, записи голоса)
хранятся только в его браузере. Поэтому главные риски — не утечка, а **сломанный сайт** (испорченные данные,
неудачное обновление, обрыв связи) и **чужой код на странице**. Проверяли и то, и другое.

## Что проверено и исправлено

| Где | Риск | Что сделано |
|---|---|---|
| Данные в браузере (`udm.*`) | испорченные или подделанные данные роняли разделы: `null` вместо полей — пустая страница «Учиться», мусор в «Группе», «Помочь проекту», игре «5 букв» | каждое поле проверяется по типу и пределам (`src/lib/safe.ts`); ключи `__proto__`, `constructor` отбрасываются |
| Коды прогресса и группы | чужой или битый код затирал свой прогресс | код принимается, только если это объект прогресса версии 1; имя и числа в коде группы ограничены |
| Ссылки (`#/dict/%`) | «битый» %-код ронял всё приложение (URIError) | безопасное раскодирование (`decodeSafe`) |
| Любой раздел | ошибка в разделе — пустой экран | «предохранитель»: «Что-то пошло не так» → «Обновить», «На главную», «Скопировать код прогресса», «Сбросить данные» |
| Запуск | не загрузился скрипт — белый экран; старый браузер — белый экран | «сторож запуска»: запасной экран; для браузеров старше 2022 года — «Браузер устарел» |
| Чужие скрипты | XSS | `{@html}` только для разметки шпаргалок, которая сначала экранирует весь текст; CSP в `<meta>`: скрипты — только свои и два встроенных с точным хэшем, `object-src 'none'`, `base-uri 'self'`; e2e-тесты падают при нарушении CSP |
| Офлайн (service worker) | mp3, открытый по прямой ссылке, сохранялся как страница приложения; ответы с ошибкой и куски (206) попадали в кэш; переполненный кэш ломал аудио | в кэш как страница — только сама страница и только HTML; кэшируются только ответы 200; ошибка записи в кэш не мешает ответу |
| Обновление сайта | 10 минут после выпуска браузер мог брать старую страницу из HTTP-кэша GitHub Pages, а она ссылается на уже удалённые файлы | страница сверяется с сервером при каждом заходе, служебные файлы при установке берутся мимо HTTP-кэша; все файлы сборки сохраняются заранее; раздел не загрузился — одна автоматическая перезагрузка. Репетиция выпуска: `scripts/qa/sw-update.mjs` |
| GitHub Actions | права на запись у шагов, где выполняется код npm-пакетов; действия по изменяемым тегам | по умолчанию только чтение, права на публикацию — только у шага deploy; действия закреплены на коммитах; `persist-credentials: false` |
| Импорт записей носителей (`scripts/tts/import_native.py`) | архив от постороннего: пути `../`, управляющие символы в именах, огромные файлы | id и имена файлов — по строгому шаблону, размеры ограничены, управляющие символы вычищаются, ffmpeg — с ограничением длительности; есть тест с «вредным» архивом |
| Напоминание (.ics) | очищенное поле времени давало файл с `NaN` | неверное время → 19:00 |
| Сборка | на сайт уходили 73 отбракованных синтеза и служебный `manifest.json` | сборка оставляет только озвучку, которую видит ученик (одно правило `usableAudio` для уроков и сборки) |

## Что осталось и почему

- **`style-src 'unsafe-inline'`** — Svelte ставит встроенные стили (анимации, отступы). Скрипты это не открывает.
- **Нет `frame-ancestors`** (запрет показывать сайт во фрейме): в `<meta>` его не задать, а заголовки GitHub Pages
  не настраиваются. Ценного для «кликджекинга» на сайте нет; встраивать сайт в LMS при этом можно.
- **`npm audit`: 2 низких** — `deepmerge` внутри `@sveltejs/vite-plugin-svelte`, работает только при сборке,
  на сайт не попадает; исправления пока нет. Для самого сайта: 0 уязвимостей.
- **Переход со старого service worker** (кэш `udm-v1`, до 30.10.2026): у ученика, у которого сайт открыт во время
  этого выпуска, раздел может «зависнуть» на загрузке — помогает одна перезагрузка. Старый код уже у учеников в
  браузерах, исправить это задним числом нельзя; начиная с этого выпуска такие переходы проходят без перезагрузки.

## Как проверить самому

```bash
npm test && npm run check     # контент, unit-тесты (в т. ч. «вредный» архив, битые коды), типы
npm run test:e2e              # все уроки, битые ссылки и данные, офлайн на боевой сборке, сторож запуска
npm audit --omit=dev          # зависимости, которые попадают на сайт
node scripts/qa/sw-update.mjs <старая-сборка> dist   # репетиция выпуска (см. комментарий в начале файла)
```
